## Root reconciliation

The original proposal's defects are design counterexamples, not executable regressions. Root walked each against the supplied command/layout contract and checked the material repository facts before synthesis:

- **Ownership:** a single agent checkout had no declared route to the proposed scaffold harness. The seam was missing. An explicit sibling path could solve it, so the review's claimed exhaustive alternatives were rejected. Fable selected agent-owned development tooling based on the first consumer.
- **Denominators and invalidity:** displaying served counts did not define a whole-scenario headline or paired infrastructure handling. Fable supplies those decisions. Implementation must keep unknown grader outcomes visible and enforce finite re-execution bounds.
- **Custody:** git confirms the trimmed vendor subject and private oracle are tracked. The claim that every subject byte would disappear was too broad. Ignored raw runs and emitted builds still need preservation for exact replay; a digest alone cannot supply missing bytes.
- **Paid phases and versions:** the original no-call check described prerequisites, not live qualification. The independent proposal incorrectly made an offline preflight cover a live fixture. Fable separates paid capacity execution and paid grading, with immutable grading versions.
- **Identity:** the original trial-set placeholder lacked an execution/result identity rule. Fable uses result for one execution, trial for one arm/scenario trajectory, and grading for versioned judgments. The implementation must define attempts and request retries without aliases or allowance resets.
- **Host effects:** the shared GPU and fixed ordering can confound timing. Future repeated studies record load and counterbalance order. Existing frozen comparisons remain unchanged.

Fable's raw synthesis remains immutable in `study-synthesis.md`. Root's acceptance adds no public type or runtime behavior. The development-tool versus campaign-record distinction follows the actual artifact role; package does not mean only tarball contents. No source rule explicitly requires another user confirmation for that interpretation. Workspace integration remains a scoped implementation obligation, not a reason to change existing authority files or weaken gates.
