# Agent evaluation terrain and naming map

## Finding

`@orkestrel/agent` is a published runtime library with a typed root entry; it does not publish an evaluation CLI. The active harness and its qualification tools live in the package campaign tree, which the scaffold contract treats as temporary. The earlier owner direction proposes a durable `bench/agent/` home in the scaffold checkout and one package-side `bench` command; that direction remains proposal-only. (`package.json:20`, `package.json:26`, `package.json:29`, `package.json:45`, `../scaffold/.agents/orchestration.md:119`, `../scaffold/.agents/orchestration.md:129`, `.orkestrel/agent/direction.md:51`, `.orkestrel/agent/direction.md:55`)

The package manifest includes only `dist/src` and `README.md`, exports only `.` and `./package.json`, and declares no `bin`. Its scripts are development gates such as `check`, `test`, `test:probe`, and `test:bench`; `test:bench` runs Vitest benchmark mode. A stable evaluation command therefore needs an explicit owner choice: a development-only sibling harness, a separate optional package with its own executable, or a deliberate expansion of the published package surface. (`package.json:20`, `package.json:29`, `package.json:45`, `package.json:50`, `package.json:56`, `package.json:68`, `package.json:69`)

## Cohesive vocabulary sketch

Keep the concepts in separate roles. A candidate namespace could be `study`; a workload definition could be a `scenario`, frozen as a manifest; a `trial` could be one model/arm trajectory; a `series` could be the ordered set of trials across arms; and `report` could name the curated blind comparison. The inherited harness already calls its workload file `scenario.json`; the successor freezes its workload, runtime, and other custody records into a manifest. One command sketch is `agent study freeze`, `agent study run`, `agent study series`, and `agent study report`. These are illustrations only. The existing CLI already uses `freeze`, `run`, `series`, `blind`, `labels`, and `report`, so a future wrapper could preserve the proven phase words while giving them a qualified namespace. (`.orkestrel/agent/instruments/harness-capacity/README.md:39`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/types.ts:68`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/types.ts:83`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/Continuous.ts:42`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/Continuous.ts:45`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/Continuous.ts:115`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/Continuous.ts:127`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/types.ts:267`, `.orkestrel/agent/instruments/harness-capacity/bench5/continuous/types.ts:278`)

`study` is an inference from the local name census, not a settled API. `bench` remains a plausible qualified command because the earlier preservation proposal already uses it, while `trial`, `series`, and `report` have precise existing harness meanings. The root still needs to decide whether the public unit is a separate optional package, a development command, or only a durable harness outside the package.
